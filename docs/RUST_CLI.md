# The one-shot commands in Rust

The daemon (`heimdalld run`) is ported (`docs/RUST_PORT.md`). This is the rest of the Go heimdalld, so that the Go binary
can go at the switch (`docs/RUST_SWITCH.md`): every subcommand of `cmd/heimdalld`, and the helpers the package ships that are
Go or Python today.

Until a command is ported, the Rust `heimdalld` hands it to the Go one kept beside it (`/usr/lib/heimdall/heimdalld-go`) with
the same arguments; a ported one is answered by Rust (`rust/heimdall/src/cli/`).

## Method

The same as the daemon's port:

- **The same arguments, output, files and exit codes.** Byte for byte wherever a script, Settings or Sarina reads the output
  (callers below). Go's `flag` package is carried over (`src/cli/goflag.rs`: the same spellings, values and error messages),
  so are Go's error texts (`src/goerr.rs`, its errno table generated by `rust/gotools/errtable`), `log` lines
  (`src/cli/golog.rs`), `text/tabwriter` (`src/cli/tabwriter.rs`), `filepath` and `os.MkdirAll` (`src/gopath.rs`), local
  time and Go's time layouts (`gotime::Time::local`, `format`), `time.ParseDuration`.
- **Go behaviour exported as shared JSON fixtures** (`internal/parity`, `testdata/parity/cli-*.json`) for the pure parts:
  parsers, decisions, file formats.
- **Differential runs on fake roots** (`rust/heimdall/tests/common`): the same fake system built twice, the Go binary run in
  one and the Rust binary in the other, then standard output, standard error, the exit code, every file under the folders
  that matter and every call to an outside tool compared. A fake root is a user and mount namespace (nothing privileged; root
  inside is the user running the tests), the real `/usr/lib` and `/usr/share` read-only, `/usr/bin` with fakes laid over it,
  and its own `/etc`, `/var`, `/run`, `/tmp` and home folders. Tools that change the system or the network are always fakes
  there (`ALWAYS_FAKE`: systemctl, nmcli, ip, curl, clamscan, notify-send, pkill, ...): each records its call and fails
  unless the test scripts it. Commands that send packets run in a network namespace of their own as well.
- **Property tests, fuzz targets and Kani harness bodies** in the normal tests, for every parser of outside input.
- Commands that change the system or the network (`lan scan` sends packets, `contain` stops services, `immunity` moves files,
  `heimdall-intel-update` downloads) are tested only against fakes and network namespaces, never against this computer or
  its network.

`rust/heimdall/tests/cli.rs` covers the command line as a whole (version, help, unknown commands, the hidden
`__write-as-owner` command of `src/safefs.rs`) and the fake root itself.

## lan

`rust/heimdall/src/cli/lan.rs` and `src/cli/lan/` (Go: cmd/heimdalld/lan.go, internal/lan): the DNS codec (`dns.rs`), discovery
(`discover.rs`: the sweep, multicast DNS, NetBIOS), Go's resolver as the reverse names use it (`resolver.rs`), the makers
(`oui.rs`), the files (`store.rs`), the scan (`scan.rs`), the sockets made as Go's `net` makes them (`net.rs`), and Go's
`strings.EqualFold`, `ToLower` and `ToUpper` on any bytes (`text.rs`; the case-folding orbits generated from Go by
`rust/gotools/foldtable`).

- **Fixture** (`testdata/parity/cli-lan.json`, written by `go test ./internal/lan -update`, `internal/lan/parity_test.go`, a
  fixed seed): 703 DNS messages and 200 names read (records and errors), the queries, 300 runs of answers absorbed, 300
  instance names, 400 names cleaned and judged (made up from the address, machine ids), 200 NetBIOS answers, 600 kinds, 120
  merges, 120 route tables, 60 neighbour tables, the makers list, 16 stores read and written back, wifi-trusted.json, nmcli's
  answers, EqualFold and the events lines. All equal in Rust.
- **`lan list`**: 19 runs in fake roots against the Go binary (stores full, missing, empty, broken, of the wrong type, a
  folder, unreadable; `--dir` spellings; usage errors; four time zones): standard output, standard error and exit codes equal.
- **`lan scan` without a scan** (each in a network namespace of its own): offline, not trusted (no file, another network,
  nmcli failing, a broken file), the router changed, a store that does not read, a folder that cannot be made, a store that
  cannot be written: output, exit code, devices.json (times aside) and the tools called equal. `lan scan` itself is still
  handed to Go until the whole scan is proved on a namespaced network.

Not 1:1, on purpose:
- A device announcing a name whose lowercase is longer than the name (`Ⱥ`, bytes that are not UTF-8) can make Go slice past
  the end of the name and panic: Go's `lan scan` then dies every 5 minutes while that device answers. Rust leaves that name
  out and goes on (`discover::instance_name`; the fixture holds two such names).
- A devices.json with a time Go cannot read: both fail with exit 1 and the same start of the message; Go also names the
  element of its layout where reading stopped.
- A /proc/net/route line of exactly 7 fields would stop Go with a panic; Rust skips it (the kernel writes 11).

cmdScanFiles; internal/immunity, internal/scan): the store (`store.rs`: the index written as Go writes it with the daemon's

drafts (`rules.rs`).

- **The steps compared** (`tests/cli_immunity.rs`, a fake ClamAV knowing one made-up signature; after every step: output,

  Sarina is contained; `take-limbo` and `analyze` by hand. `rule`: drafts as a user and as root, a refused draft, an unknown
  sample, a missing file, `list`, `show`, `test` passing and failing (`--fp` before and after the id), `approve` refused by
  the guard without a terminal, `reject`. `scan-files`: usage errors, a scan as root and as a user, `--state` remembering
  unchanged files and forgetting them when a rule is added, `--exclude` folders and globs (a malformed one), `--max-mb`, a
  link, an unreadable file, `./` and trailing-slash roots, and a ClamAV that reports nothing.
- Unit tests: Go's own `filepath.Match` table; every cut and one-byte change of a real program's first 4 KiB through the ELF
  reader.

Not 1:1, on purpose:
- The samples' gzip bytes: flate2 compresses differently from Go; the content is the same (checked against its SHA-256 on
  every read) and each program reads the other's samples.
- A file name with a character above U+00FF: Go cannot write it into the gzip header and keeps an empty, broken sample (the
  file can never be released); the port keeps the sample without the name (`a_name_go_cannot_write_into_gzip_keeps_a_good_
  sample` shows both).
- A damaged sample reports `gzip: invalid header`, `gzip: invalid checksum`, `EOF` or `unexpected EOF`; Go's inflater can also
  name the offset where the data broke.
- An ELF file Go refuses for a compressed section it cannot inflate, or reads through one, may get a different ELF part in
  its report (no real program has compressed sections there).
- The analysis's HTTP request to Limbo carries the same method, path and body; its headers are not Go's byte for byte
  (Limbo reads only the body).

## Wi-Fi

`heimdalld wifi-health [--speed] [--json] [--iface IF] [--api ADDR]` is Rust (`src/cli/wifihealth.rs` and
`src/cli/wifihealth/`): the default route's Wi-Fi interface from `/proc/net/route` and `/sys/class/net/IF/wireless`, `iw`
before and after (power saving, link, station dump), the router and the internet pinged at once while NetworkManager's scan
list and the device count (`GET /v1/lan/devices`, 3 s, Go's decoder rules: the first JSON value, every field's type checked)
are read, the optional download from the first https mirrors of `/etc/pacman.d/mirrorlist` (two streams with Go's `Range`
headers, about 8 s, the internet pinged meanwhile, redirects followed), all inside 90 seconds; the same findings, verdict,
summary, JSON (Go's `json.Encoder`: field order, `omitempty`, `null` for no neighbours, nothing at all when a number is not
finite) and text, the same exit codes (1 only when `iw` is missing).

What it took to be the same:

- Go's patterns with `\s` and `\d` written as Go's ASCII classes; Go's number parsing with its errors ignored (overflow kept:
  a huge frequency is `int(+Inf)`, which on amd64 is the smallest int); bytes that are not UTF-8 carried through as Go sees
  them (one character to the patterns, one U+FFFD each in JSON, raw in text: `gostr.rs`).
- Go's `sort.Slice` (pdqsort, not stable) ported step for step (`gosort.rs`), since networks with the same signal are listed
  in the order Go's algorithm leaves them.
- **Go 1.27's JSON encoder writes a byte that is not UTF-8 as the character U+FFFD itself**, not as the escape `\ufffd` older
  Go wrote (checked with the Go that builds heimdalld). `gostruct::write_bytes` still writes the escape; it is shared with
  the daemon's API, so it is left alone here and reported.
- The HTTP client (`http.rs`): HTTP/1.1, one request per connection, TLS by rustls with the authorities Go reads
  (`SSL_CERT_FILE`, Go's file list, `/etc/ssl/certs`); TLS 1.3 and 1.2, as Go offers them (the `tls12` feature of rustls is
  on for this; the mesh keeps TLS 1.3 only in its own configuration). Errors carry Go's words where the report quotes them
  ("no such host", "connection refused", "certificate signed by unknown authority", ...).

Proof:

- `testdata/parity/cli-wifi.json` (`internal/parity/cli_wifi.go`, a fixed seed): 206 `iw` texts, 201 scan lists, 201 ping
  outputs, 1,517 frequencies, 776 overlap questions, 300 `sort.Slice` orders and 160 whole made-up situations (good, busy,
  weak, crowded, a provider's hotspot on our radio, power saving, speed tests, unknown bands, names that are not UTF-8),
  each report's JSON and text byte for byte (`tests/cli_wifi.rs`).
- Both binaries in fake roots (`tests/cli_wifi_run.rs`): a dummy `wlan0` in a network namespace of its own, fake `iw`,
  `ping`, `nmcli`, a fake API on 127.0.0.1:8930 (Python's http.server), and for `--speed` a mirror over TLS (`openssl
  s_server` with a test authority made for the run): 19 situations, text and JSON, flags in Go's spellings, `-h`, a wrong
  flag, the API down or broken, no mirror list, the mirror unreachable, `iw` missing, no default route. Output (the measured
  speed and the time aside), errors, exit codes and every tool call equal.
- Fuzz targets `wifi_link`, `wifi_scan`, `wifi_ping`, `wifi_devices` (seeds in `rust/fuzz/seeds`), 4 property tests and 2
  Kani harnesses with their claims checked exhaustively over a range (`tests/cli_wifi_fuzz.rs`).

Not 1:1 (all where nothing reads the difference): one request per connection and HTTP/1.1 only (Go may use HTTP/2 with a
mirror that offers it; the bytes counted are the same file); no HTTP proxy from the environment (Go's client honours
`HTTPS_PROXY`; Settings runs the check without one); a certificate failure that is not one of the usual kinds is worded by
rustls, not Go, in the speed test's error.

## trust, mesh, scan

**trust** (`src/cli/trust.rs`, the owner's side added to `src/trust.rs`): `init`, `status`, `mode`, `sign` (with
`--watched`), `forget`, `restore`, `verify`, `watch add|remove`, with Go's texts, exit codes and files. The key is Go's
(`owner.key`: base64 of the 64-byte ed25519 private key, the seed then the public key; `owner.pub`: base64 of the public
key), made with ring from 32 random bytes as Go's `ed25519.GenerateKey` does; the list is Go's `json.MarshalIndent(...,
"  ")` with a newline, signed over its exact bytes (Ed25519 is deterministic, so the same key and list give Go's signature
byte for byte); `watch.json` and `mode` as Go's `SetWatch` and `SetMode` write them, each through `NAME.tmp` and a rename;
restore writes through `safefs` as the file's owner. `HEIMDALL_TRUST_DIR` works as in Go (tests: no root needed, no restart).

Proof:

- `testdata/parity/cli-trust.json` (`internal/parity/cli_trust.go`, nothing random in it, so Go checks it is current on
  every run): 4 keys from fixed seeds, 6 signed lists (odd paths: `<>&`, quotes, U+2028, control characters, bytes that
  are not UTF-8, a cut sequence, U+FFFD itself, the zero time and year 9999) with their bodies and signatures byte for
  byte, 5 watch lists (nil, empty, full), 10 modes and 71 base64 strings: 96 cases, all equal.
- Differential runs in fake roots (`tests/cli_trust.rs`), each step's stdout, stderr, exit code, the calls to outside tools
  (`systemctl try-restart heimdall.service`), every file under /etc/heimdall, the user's home, /etc/sarina and /srv with
  its owner compared, then each binary's `status` and `verify` on the other's files: from `init` (20 steps: usage, before
  init, `--user` unknown, as a user, twice, every mode spelling, `sign --watched`), signing with a known key (37 steps:
  refusals, relative paths, folders, verify of watched/listed/given paths, changed/deleted/planted files, restore as the
  user (uid 1000) through `__write-as-owner`, restore refused through a link, a missing approved copy, forget, watch
  add/remove down to `null` lists, a folder of 5,001 files, a tampered list, a missing key), names that are not UTF-8
  (6 steps) and `HEIMDALL_TRUST_DIR` (4 steps). All equal.
- Properties (base64 round trip; any signed list reads back and one flipped byte is refused), the `trust_list` fuzz target
  extended to key files, the owner's list writer and base64, a Kani harness for the base64 writer with an exhaustive
  stand-in test.

Not 1:1: a key file whose public half does not belong to its seed (only a damaged file) is refused ("the signing key

## Differences from Go

- The Go that builds heimdalld (1.27, json v2 underneath `encoding/json`) writes each byte of a string that is not UTF-8 as
  U+FFFD itself, not as the escape `\ufffd` (checked for map keys and struct fields; trust's list follows it).
  `gostruct::write_bytes` still writes the escape.

- `help` prints Go's usage, then the commands only the Rust heimdalld has (`run --shadow`, `replay`, `rules check`).
- `__write-as-owner` (safefs): the child started as a file's owner has no supplementary groups; Go's kept root's
  (`NoSetGroups`). The file written is the same.
