# The one-shot commands in Rust

The daemon (`heimdalld run`) is ported (`docs/RUST_PORT.md`). This is the rest of the Go heimdalld, so that the Go binary
can go at the switch (`docs/RUST_SWITCH.md`): every subcommand of `cmd/heimdalld`, and the helpers the package ships that are
Go or Python today.

Until a command is ported, the Rust `heimdalld` hands it to the Go one kept beside it (`/usr/lib/heimdall/heimdalld-go`) with
the same arguments; a ported one is answered by Rust (`rust/heimdall/src/cli/`).

## Method

The same as the daemon's port:

- **The same arguments, output, files and exit codes.** Byte for byte wherever a script, Settings or Sarina reads the output
  (callers below). Go's `flag` package is carried over (`src/cli/goflag.rs`: the same spellings, values and error messages),
  so are Go's error texts (`src/goerr.rs`, its errno table generated by `rust/gotools/errtable`), `log` lines
  (`src/cli/golog.rs`), `text/tabwriter` (`src/cli/tabwriter.rs`), `filepath` and `os.MkdirAll` (`src/gopath.rs`), local
  time and Go's time layouts (`gotime::Time::local`, `format`), `time.ParseDuration`.
- **Go behaviour exported as shared JSON fixtures** (`internal/parity`, `testdata/parity/cli-*.json`) for the pure parts:
  parsers, decisions, file formats.
- **Differential runs on fake roots** (`rust/heimdall/tests/common`): the same fake system built twice, the Go binary run in
  one and the Rust binary in the other, then standard output, standard error, the exit code, every file under the folders
  that matter and every call to an outside tool compared. A fake root is a user and mount namespace (nothing privileged; root
  inside is the user running the tests), the real `/usr/lib` and `/usr/share` read-only, `/usr/bin` with fakes laid over it,
  and its own `/etc`, `/var`, `/run`, `/tmp` and home folders. Tools that change the system or the network are always fakes
  there (`ALWAYS_FAKE`: systemctl, nmcli, ip, curl, clamscan, notify-send, pkill, ...): each records its call and fails
  unless the test scripts it. Commands that send packets run in a network namespace of their own as well.
- **Property tests, fuzz targets and Kani harness bodies** in the normal tests, for every parser of outside input.
- Commands that change the system or the network (`lan scan` sends packets, `contain` stops services, `immunity` moves files,
  `heimdall-intel-update` downloads) are tested only against fakes and network namespaces, never against this computer or
  its network.

`rust/heimdall/tests/cli.rs` covers the command line as a whole (version, help, unknown commands, the hidden
`__write-as-owner` command of `src/safefs.rs`) and the fake root itself.

## Callers that read the output

| Caller | Command | What it reads |
| --- | --- | --- |
| Yggdrasil Settings (`packages/settings/src/wifihealth.rs`) | `heimdalld wifi-health --json [--speed]` | the JSON report on stdout; stderr's text when the exit code is not 0 |

| Labyrinth `labyrinth-scan-downloads`, `labyrinth-security-setting` | `heimdalld scan-files --state FILE PATH` | `INFECTED PATH: SIGNATURE` lines; exit codes 0, 1, 2 |

| units | `lan scan` (timer, 5 min), `immunity inventory` (timer, daily), `immunity run-requests` and `contain run-request` (path units) | the exit code, the journal |

## contain and admin

`src/cli/maintenance.rs` on `src/maintenance.rs` (now with Go's `Open`, `Write`, `Clear`, `Describe` and `Duration.Round`).

- **maintenance** (`on --for D --reason R`, `off`, `status`, `--config`): proved in fake roots against the Go binary (47 runs:
  every action as root, as a user and through sudo, `maintenance_actors`, the window capped at four hours, a missing
  `/etc/heimdall`, damaged and unreadable configs with Go's sixteen kinds of JSON error, flag errors, `-h`), the window file
  byte for byte, and the Go fixture `testdata/parity/cli-admin.json` (199 cases: `Describe` over five zones and eleven
  remaining times, `Open` + `Write`, `Read` of odd files, `Round` at the ends of the range). Properties: a window never
  lasts more than four hours (also a Kani harness, `src/maintenance.rs`), `Round` against exact arithmetic, a window read
  back is capped.
- **grant** (`status`/`list`, `approve ID [--for D]`, `deny ID`, `tier N`, `revoke`, `off`): `src/cli/grant.rs`, both files
  read and written through `gostruct` as Go's `encoding/json` does with Go's structs. Proved in fake roots: 23 runs with
  standard input not a terminal (status of every combination of files, damaged, a folder or a link in a file's place, a
  requests file the user cannot read, the refusals) and 27 on a pseudo-terminal with the answer typed in (approve, deny,
  `--for` before and after the id, an escalation for more than a day, "no" and end of input at the prompt, `tier` with
  Go's `fmt.Sscan` readings of `09`, `-1`, `x`, `revoke`, `off`, a missing `/etc/heimdall`, and the guard refusing
  `SUDO_USER=sarina` and a parent process named sarina), with the requests file left to heimdalld's account as Go leaves
  it. The fixture: 234 decisions through Go's store (every operation on nine decision files, with and without requests:
  the files after byte for byte, the errors) and 14 made-up `/proc` trees through the guard (programs by link and by first
  argument, a missing status, no parent, chains longer than 64). Properties (a tier is only ever 0-3; `Sscan`), fuzz
  target `grant_files` (any bytes as either file; what reads is written back and reads the same), smoke-run in the tests.
- Not 1:1 inside, the same outside: the daemon's JSON reader names a config's wrong type differently from Go
  ("number 5 into Go struct field net_ports"); the commands print Go's text (`cli::maintenance::go_config_error`). The
  daemon's own message on a damaged config (`run`) is unchanged.
- `gostruct` (shared) now words two JSON type errors as Go 1.27 does: no "Go struct field" when the path ends at a list's
  index ("into Decisions.escalations.0 of type grants.Escalation"), and a wrong kind for a time as for any type ("number
  into Go struct field ... of type time.Time"). Only error texts of damaged files change; nothing the daemon decides.
- Not 1:1: a time that is a string but not RFC 3339 is reported as `parsing time "x" as RFC 3339: cannot parse`, where Go
  names the part that failed (`... as "2006-01-02T15:04:05Z07:00": cannot parse "x" as "2006"`). Only for damaged files.
- `grant status` lists requests with equal times in the file's order; Go's sort is not stable past twelve requests (times
  are to the nanosecond, so equal ones do not happen in practice).

## trust, mesh, scan

**trust** (`src/cli/trust.rs`, the owner's side added to `src/trust.rs`): `init`, `status`, `mode`, `sign` (with
`--watched`), `forget`, `restore`, `verify`, `watch add|remove`, with Go's texts, exit codes and files. The key is Go's
(`owner.key`: base64 of the 64-byte ed25519 private key, the seed then the public key; `owner.pub`: base64 of the public
key), made with ring from 32 random bytes as Go's `ed25519.GenerateKey` does; the list is Go's `json.MarshalIndent(...,
"  ")` with a newline, signed over its exact bytes (Ed25519 is deterministic, so the same key and list give Go's signature
byte for byte); `watch.json` and `mode` as Go's `SetWatch` and `SetMode` write them, each through `NAME.tmp` and a rename;
restore writes through `safefs` as the file's owner. `HEIMDALL_TRUST_DIR` works as in Go (tests: no root needed, no restart).

Proof:

- `testdata/parity/cli-trust.json` (`internal/parity/cli_trust.go`, nothing random in it, so Go checks it is current on
  every run): 4 keys from fixed seeds, 6 signed lists (odd paths: `<>&`, quotes, U+2028, control characters, bytes that
  are not UTF-8, a cut sequence, U+FFFD itself, the zero time and year 9999) with their bodies and signatures byte for
  byte, 5 watch lists (nil, empty, full), 10 modes and 71 base64 strings: 96 cases, all equal.
- Differential runs in fake roots (`tests/cli_trust.rs`), each step's stdout, stderr, exit code, the calls to outside tools
  (`systemctl try-restart heimdall.service`), every file under /etc/heimdall, the user's home, /etc/sarina and /srv with
  its owner compared, then each binary's `status` and `verify` on the other's files: from `init` (20 steps: usage, before
  init, `--user` unknown, as a user, twice, every mode spelling, `sign --watched`), signing with a known key (37 steps:
  refusals, relative paths, folders, verify of watched/listed/given paths, changed/deleted/planted files, restore as the
  user (uid 1000) through `__write-as-owner`, restore refused through a link, a missing approved copy, forget, watch
  add/remove down to `null` lists, a folder of 5,001 files, a tampered list, a missing key), names that are not UTF-8
  (6 steps) and `HEIMDALL_TRUST_DIR` (4 steps). All equal.
- Properties (base64 round trip; any signed list reads back and one flipped byte is refused), the `trust_list` fuzz target
  extended to key files, the owner's list writer and base64, a Kani harness for the base64 writer with an exhaustive
  stand-in test.

Not 1:1: a key file whose public half does not belong to its seed (only a damaged file) is refused ("the signing key
cannot be read ... is not a key"); Go would sign with it and write a list that never verifies.

**scan** (`src/cli/scan.rs`): one look through the daemon's own detectors and sources, as Go's `cmdScan`: Sarina's
sessions (no state; the issues as warnings), Limbo's whole log (no offset; unparseable lines counted), the vaults (nothing
remembered), the watched files (with the FIM state file), the host's load and the ecosystem's ports (`PortWatcher` reporting
on its first look, as Go's `Poll` alone does; the daemon's first look still only learns), the tool rules where the system
asks for them, the ring of `ring_size`, the findings oldest first as alert lines; exit 0, 1 or 2 as Go. The config is read
with Go's error texts (`Config::load_go`).

Proof (`tests/cli_scan.rs`, fake roots with a network namespace of their own, 21 steps): planted sessions (injection,
keys, permission denials, a zero-width space, a system message, a tool call), Limbo lines (a guest without policy, a LAN
probe, a held file, a broken line, a cut line), vault notes (and the ones skipped), a listener on 0.0.0.0:8765, watched
files changed and deleted between two looks, only info left, nothing left, the FIM state unwritable, a ring of 2, every
flag and config error, a damaged session, a missing vault and Limbo log, Limbo's log a folder, the session folder gone:
stdout (alert lines, times aside), stderr, exit codes and the FIM state file equal.

Not 1:1: for a config with a wrong type inside a list or a list where none belongs, Go 1.27 names the element and the
list's type ("cannot unmarshal string into Config.net_ports.1 of type int"); the port says "Go struct field
Config.net_ports of type int" ("of type slice" for the list). Only the message of a broken config differs.

**mesh**: not ported yet (it goes to the Go binary).

## Differences from Go

- The Go that builds heimdalld (1.27, json v2 underneath `encoding/json`) writes each byte of a string that is not UTF-8 as
  U+FFFD itself, not as the escape `\ufffd` (checked for map keys and struct fields; trust's list follows it).
  `gostruct::write_bytes` still writes the escape.

- `help` prints Go's usage, then the commands only the Rust heimdalld has (`run --shadow`, `replay`, `rules check`).
- `__write-as-owner` (safefs): the child started as a file's owner has no supplementary groups; Go's kept root's
  (`NoSetGroups`). The file written is the same.
